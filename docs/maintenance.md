**First run found one flag — verified as a false positive, not a real leak.** gitleaks'
`linkedin-client-id` rule matched `loginUrl: "https://www.linkedin.com/login"` in
`src/pull/platforms/linkedin.ts` (commit `ccc9db6`, 2026-07-03) — that's LinkedIn's own
public login page URL, not a credential; confirmed by reading the flagged commit directly
rather than assuming. The bundled gitleaks version rejected a fingerprint-only `[allowlist]`
table (its schema needs `commits`/`paths`/`regexes`/`stopwords`), and a `regexes` check on the
literal URL string still didn't suppress it against the live CI run, so the final fix
allowlists by `paths` on this one small (107-line) file instead — read in full first to confirm
it holds nothing else secret-shaped (just this login URL plus one public analytics-page URL).
Narrower than a rule-wide or repo-wide exemption, but broader than a single-fingerprint match;
documented in a `.gitleaks.toml` comment. Nothing was rotated or treated as a real leak because
it isn't one.

## Filed as Backlog cards

Three agent-loop / judgment gaps this audit surfaces, filed to `Backlog`
(status Backlog, not promoted) with `ORIGIN: maintenance-audit 2026-07-20`:

- **Wire an event-driven deep-security-review trigger** for PRs touching
  secrets/credentials/auth/publish-adapter code. Loop-table row "Deep
  security review (agent)" is `event-only` for Class A — nothing currently
  detects "this PR touches `.env`-adjacent config, `src/pull/login.ts`,
  `src/publish/*`, or similar" and routes it to a security-review pass
  before merge. Today that only happens if a human or the conductor
  happens to notice.
- **Monthly codebase-health-report loop** (hotspot/complexity/dead-code
  report → refactor cards). Class A target is monthly; nothing currently
  produces this report for content-agents. (Not a refactor loop itself —
  a report that files cards, per the rubric's own guardrail against
  calendar-driven refactoring.)
- **`src/review/serve.ts` binds to all interfaces, not localhost-only,
  despite the printed URL claiming otherwise.** `server.listen(PORT, ...)`
  passes no host argument, so Node binds `0.0.0.0` by default — the console
  log says `http://localhost:${PORT}`, but the server is actually reachable
  from the LAN. This server has zero auth and both reads and writes
  content-review/publish state (approve/revise/discard, and some routes
  shell out via `execFile`). Concrete, class-A-appropriate security finding
  from this audit's review pass, not a hypothetical — filed as its own
  card rather than folded into the health-report loop above since it's an
  immediate fix candidate, not a report-driven hotspot.

Not filed (on-demand / no repo-specific gap found):
- Docs drift scan — Class A target is on-demand, not a standing loop; no
  card needed right now.
- Bug triage loop — event-only (CI failure → card) for Class A; this is
  the standard conductor build/verify/self-vet loop's job, not a
  content-agents-specific wiring gap.
