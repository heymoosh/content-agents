## Purpose and evidence rules

The product promise: **Muxin supplies ideas and direction; Studio helps develop them, adapt them
for platforms, publish what she approves, and learn from the results.** The interface should make
that work understandable without requiring her to operate the underlying publishing machinery.

This file answers: what did we promise, is it built, what proves that, and what still blocks it?
It is not a transcript, audit log, or substitute for the repository operating policy in
[AGENTS.md](../AGENTS.md) and [CLAUDE.md](../CLAUDE.md).

Product sources are [Muxin's vision](Muxin's%20Vision%20for%20Content%20Studio.md), the
[foundational UX vision](content-studio-vision.md), and subsequent explicit owner corrections.
The room-level scope below incorporates the September 13 confirmation. Detailed inherited methods
are distinguished from that scope; they do not all become newly confirmed requirements by reference.

- **Built: Yes** means the relevant implementation was traced in source. It does not mean the whole experience passed live QA.
- **Built: Partial** means a narrower implementation exists or a required connection is missing.
- **Built: No** means the named outcome is absent or explicitly refused at the inspected boundary.
- **Verification gap** means proof is missing; it is not automatically a missing feature or failed implementation.
- **Recorded live evidence** means the latest relevant prior result, retained from the previous master. It was not repeated in this review and is not a guarantee that credentials remain healthy.
- Test files cited below establish what coverage exists; this documentation review did not execute them.
- Newer relevant evidence supersedes older status. A newer date alone cannot turn a narrower test into proof of a broader promise.
- Update a requirement's status in place. Keep only the latest useful evidence pointer and unresolved limitation. Git retains the old narrative.
