# SLICE-5H: separate a configured quote card's on-image quote from its post text

Protocol: `AGENTS.md` → `## Slice protocol`. Read that and this file only.
Do not open `docs/content-studio-master-status.md` unless a heading is cited below.
Do not load the repository for context. Do not commit.

## Goal

A quote-card variant generated by the Content Studio's configured path ends up with **two distinct
texts** instead of one string doing both jobs:

- `derivatives/<id>.md` — the **post text**: the per-platform context that frames the quote. This is
  what the review-queue row displays and what `publish:cards` ships as the post body alongside the
  image. Unchanged file path, unchanged consumers.
- `derivatives/<id>-quote.md` — a **new companion definition derivative**: the short verbatim quote
  that gets drawn ON the image. `platform: quote-card`, `source_lines` naming the quote's own
  source line(s), no spin, body ≤180 characters, body only (no frontmatter noise beyond that).

The configured media plan for a card renders from the **quote** file, not the post body.

Today one drafted string is the derivative body, the render plan's `sourceText`, AND the text
painted onto the card (`jobs.ts:1184` → `configuredMediaPlan`, `configured-media.ts:125` →
`renderStill`, `render.ts:60`). The consequence is that a Studio card either paints a full platform
post onto the image or leaves a bare quote as the post body. Either way the quote ships without
context, which is the failure `/atomize` step 7 was built to prevent (Muxin, 2026-07-03: a card is a
bare-quote image "with its OWN per-platform CONTEXT caption — so the quote never ships alone, out of
context"). This slice ports that separation onto the configured path.

Also fix the drafting blind spot this exposed: initial configured drafting gives a card variant no
card-specific instruction at all. `configuredTreatmentInstruction` (`jobs.ts:349-362`) knows only
generic treatment keys. The only card awareness in the repo is `isCardCaption` in the REVISE path
(`jobs.ts:129,150`), which (a) applies only to editing an existing file and (b) uses the regex
`^quote-card-\d+-[a-z]+$`, which does not match a configured variant id. A card variant's post text
must be drafted as context, under the same instruction the revise path already uses: give the setup,
mechanism or stakes around the quote, and never restate the quote that is on the image.

## Difficulty

with its own extraction-first obligation) and re-points the render plan. Prose-composing behavior,
so it carries the stronger content-generation gates.

## Acceptance

- [ ] For a configured variant whose `media` is `static-quote-card` or `animated-quote-card`,
      generation writes BOTH `derivatives/<id>.md` (post text) and `derivatives/<id>-quote.md`
      (on-image quote). For every other media value, exactly the files written today are written,
      with byte-identical content for the same inputs.
- [ ] The quote file carries `platform: quote-card`, a `source_lines` list, no `spin`/`angle`, and a
      body of at most 180 characters.
- [ ] The quote body is **verbatim from the source** — extraction-first, not composed. The post text
      may be treated/spun within the existing configured-treatment guardrails; the quote may not.
- [ ] The card's media plan `sourceText` is the QUOTE file's body, not the post body, so the
      renderer paints the quote. Proven by asserting the plan/stage content, not by asserting that a
      function was called.
- [ ] The runtime's card branch passes the quote file's name to the renderer
      (`configured-media-runtime.ts:307-311`), so `renderStill` reads `derivatives/<id>-quote.md`.
- [ ] A card variant's POST text is drafted as context: the drafting instruction tells the model to
      give the setup, mechanism or stakes around the quote and never to restate the quote. The
      existing revise-path wording (`jobs.ts:150`) is the reference; do not invent a second
      vocabulary for the same idea.
- [ ] `isCardCaption` (`jobs.ts:129`) recognizes a configured card variant id, or the card-awareness
      is routed some other way that a test proves. Today's regex matches only legacy
      `quote-card-N-<target>` ids; a Studio id must not silently fall through to the generic path.
- [ ] No em dashes and no AI tells in anything composed, per `config/voice.yaml`.
- [ ] Nothing publishes and no review status changes as a result of this slice.

## Found during this slice, NOT fixed here — needs its own slice

**Studio-generated cards cannot reach the card publisher.** Configured card rows keep
`platform: "linkedin"` / `"x"`, but `publish:cards` selects only `quote-card` platforms
(`src/publish/cards.ts:78`), so a card generated in the Content room never enters that publisher.
Pre-existing, unrelated to this change, and deliberately out of scope — but it means 5H makes the
card's post text correct without yet making the card publishable from Studio. Pair it with the
other deferred card item: configured generation renders a SEPARATE image per platform
(`jobs.ts` output path is keyed per variant id) instead of sharing one card across platforms the
way `/atomize` does.
